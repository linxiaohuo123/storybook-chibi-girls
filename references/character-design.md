# 角色主题、差异与清单

## 用可见的小事表达故事

采用“子主题身份 + 正在做的小事 + 一个主道具 + 一个服装呼应元素”。例如：蒲公英邮差正在递出一封带花形封口的信，邮包扣也使用花形。不要依赖背景邮局、画面标题或长段设定让主题成立。

装饰集中在一个焦点和少量呼应位置：主道具、帽饰、裙边纹样。花纹、蕾丝、蝴蝶结可以精细，但不能每个空白都填满。

## 保持画风，变化身份

新角色固定：头身比例区间、五官画法、线条语言、2D 平涂、背景与构图规范。

新角色变化：`theme`、`hair_style`、`hair_color`、`outfit_silhouette`、`signature_prop`、`pose`、`expression`。每两名至少四项不同，并在发型轮廓、服装轮廓或姿态中至少一项有实质区别。`palette_id` 用于颜色安排，不用于冒充结构差异。

先检查整个批次的“发型 × 表情 × 姿态”，再写完整提示词。小批次尽量不重复表情；大批次允许有限复用，但不连续复用相同眼型、嘴型与头部倾向。总主题固定时使用不同子主题。

只改配色或清理杂线属于 `edit`，不执行“四项不同”要求，否则会破坏用户要保留的人物。批量编辑也应逐个保持各自身份。

## 结构化角色卡

需要批量去重或续做时创建下列 JSON；单张简单任务可在当前上下文保留同样字段，无需为了形式另存文件。

```json
{
  "mode": "new_character",
  "characters": [
    {
      "id": "apricot-postgirl-01",
      "theme": "杏桃邮差",
      "story": "递出一封花形封口的春日来信",
      "hair_style": "齐刘海短波波头",
      "hair_color": "暖栗棕",
      "outfit_silhouette": "短披肩加A字背带裙",
      "signature_prop": "花形封口信",
      "pose": "略侧身单手递信另一手扶斜挎包",
      "expression": "弯眼开口微笑",
      "palette_id": "apricot-sky",
      "palette_roles": {
        "hair": "暖栗棕单色平涂",
        "main_outfit": "杏桃色裙身",
        "secondary": "晴空蓝短披肩",
        "buffer": "奶白袖口和领子",
        "accent": "青绿色邮包扣"
      }
    }
  ]
}
```

命令：`python3 scripts/check_diversity.py --plan /absolute/path/plan.json`。存在可用历史时再加 `--history /absolute/path/accepted.jsonl`。脚本是字段比较器，不理解所有同义词，也不证明生成图本身不同，仍需看轮廓与表情。

## 续做历史

仅在已有可写、可持续访问的项目输出位置或用户要求持续记录时保存 `accepted.jsonl`，每行一个已检查并接受的角色卡，可加 `quality_status: "passed"`、真实图片标识、实际提示词与时间。不要编造图像路径或模型版本。

只有当前对话可用时，明确只能避开本对话已见角色；不要声称永久记住所有旧图。历史无法读取时继续检查本批次并说明限制，不假设历史为空，不覆盖既有记录。设计稿、失败稿与待复查图不要加入已接受历史。
