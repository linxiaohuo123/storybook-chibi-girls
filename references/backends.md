# 生图后端与能力边界

## 以当前实际工具为准

本技能提供设计、生产与检查流程，不是训练后的图像模型，不提供独立推理服务。每次执行先看当前可用工具的 schema 和图像技能；不得把某个会话的函数名、参数名或弃用信息写成永久事实。

- 优先使用当前可用的内置图像工具，不要求用户额外提供 API Key。无工具时可交付方案／提示词并说明未出图，不能假装已有成品。
- 内容指令放入当前接口规定的位置：schema 有必需的字符串 `prompt` 就传完整字符串；另一环境有不同协议时遵守其协议。不要无条件调用 `image_gen.text2im`、`image_gen.imagegen` 或无条件传 `prompt: null`。
- 仅当工具实际提供对应字段时设置尺寸、透明度和参考输入。白底要求不透明；只写“1:1”不证明输出具有某个精确像素尺寸。
- 若当前工具提供 `referenced_image_paths`，先看本地参考再按其规则传入；若只可引用最近图片，选最少必要数量。工具规定互斥的参考机制不得同时使用。
- 新图无参考时不添加虚构路径。有参考时区分新角色的风格参考与编辑目标，声明哪些设计保持、哪些允许变化。
- 一个角色一张独立图；多张分别生成。不用拼图切割代替独立成品；并发、单次数量与重试方式以实际工具规则为准。
- 图像编辑使用当前环境规定的图像编辑工具。默认不运行脚本自动改像素、抹背景或改尺寸；用户明确要求确定性图像处理且环境允许时，才选用该流程，并先核实透明度、浅色衣物和输出覆盖等风险。
- 遵守当前工具的展示和保存方式。已自动展示／保存的图，不为获得路径额外下载或重新上传；可看图先视觉检查，不能做像素检查就标明不可用。
- 工具成功不代表图像合格。看不到实际输出必须标记 `not_reviewed`；不捏造图像、不用 SVG 占位冒充成图，也不自动切换到收费外部服务。

## 用户指定自己的 API 时

先完成角色卡和部位配色，再根据实际接口文档或已配置客户端确认：地址、模型标识、鉴权、生成／编辑能力、参考输入、允许尺寸、响应字段、轮询及费用约束。核实当前文档，不从名称猜协议。

“New API”“OpenAI 兼容”“image2.6”“ima 2.6”等名字不足以确定真实模型 ID；`/images/generations`、`/images/edits`、`response_format`、`negative_prompt`、`seed` 或 `style_strength` 不得默认存在。

密钥通过现有安全配置读取，不要求在聊天粘贴完整密钥，不写入技能、提示词、日志或示例。没有配置仍可给完整提示词，但应说明外部后端未接通，不声称端到端测试通过。

已指定外部接口时不悄悄改用内置工具。超时不等于上游没有生成，先查询实际任务状态；不对非幂等付费请求无条件重试。没有实际任务 ID、模型名、seed 或图片路径就不要编造。

## 验证边界

技能文档检查、脚本测试、提示词规划检查、生图效果验证与客户验收是不同证据。只报告实际完成的层级；不能用前一层的通过替代后一层。未接入的私有接口仍是数据不足。
